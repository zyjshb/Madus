# 音乐发现（1.18.0）

本次目标：推荐专注歌曲；按照实际音乐偏好找新歌，减少重复和普通视频混入。

## 实现

- 初始推荐、续播、点赞插入、待播重排与音源兜底均走音乐筛选。候选不足也不回退全站视频。
- 分类、标题、标签和时长联合筛选；搜索保留真实分区/标签。音乐搜索这个来源标签本身不视为歌曲证据。
- 曲风、语言、氛围从标题及标签提取。收藏、本地歌单和有限的 B 站收藏抽样作为种子，音乐搜索轮换主题和页码，相关歌曲扩展新候选。
- 搜索/歌单收听也产生播放、听过半、听到九成信号。暂停和大幅拖动不累计为实际听歌时长。
- 跨会话读取近 14 天的听歌事件避重；标题中的明确歌名用于合并不同上传版本。单会话保留最多 800 个已播 ID。
- 长期信号保留窗口 180 天、45 天衰减参数，事件总量上限 6000；持久收藏可用于久未打开后的偏好重建。
- 快速跳过降低短期兴趣；两次同细类跳过触发短期冷却，不屏蔽整个音乐区。重排不放宽歌曲筛选、已听/屏蔽约束。
- 最多并发三个首批搜索/相关召回请求；事件写入串行化，收藏及历史持久化音乐标签。

## 自动检查

`gradlew.bat :app:testDebugUnitTest :app:assembleRelease --offline`

新增领域回归覆盖：视频排除、英文子串误判、正常歌名保留、曲风标签、搜索主题轮换、冷却、历史过期、同歌不同上传、同 BVID 不同本地 ID、纯音乐队列补满、长期偏好及拖动/暂停信号。

## 真机验收

当前环境没有连接 Android 设备，以下尚未完成：

1. 保留旧数据覆盖安装，从推荐进入连续听歌，检查首批加载时间及歌曲比例。
2. 喜欢几首同曲风音乐，在搜索和歌单里完整收听，观察后续新歌是否更接近偏好。
3. 连续跳过同曲风歌曲，确认后续调整且不会把全部音乐屏蔽。
4. 听完一批后重启，检查已听 ID 和明确同名版本不会立刻再次被推荐。
5. 推荐预取期间切换本地歌单，确认不会混入旧推荐请求的结果；检查后台续播。

## 边界

依赖 B 站接口可用性、分类及标题质量，不是音频级歌曲识别。分类缺失、跨区投稿、同名不同歌及复杂版本标题可能误判。严格过滤会减少候选数量；少于 70 秒、超过 7 分钟或未知时长的内容不自动推荐。没有新增版权曲库、云端协同过滤或大规模推荐模型，也尚无留存提升的实测数据。
